# MiniBank

MiniBank는 Spring MVC의 요청 처리 흐름과 계층 분리를 익히기 위해 만든 서버 렌더링 방식의 미니 인터넷뱅킹 프로젝트입니다. 회원과 계좌를 메모리에 저장하고, 회원가입부터 계좌 개설·조회·입금·출금까지 하나의 웹 흐름으로 연결했습니다.

## 구현된 기능

### 회원

- 회원가입 Form과 회원 정보 저장
- 중복 로그인 ID 검사
- 회원가입 성공 후 계좌 개설 화면으로 이동하는 PRG 흐름
- 로그인 화면 제공

### 계좌

- 존재하는 회원의 계좌 개설
- 12자리 계좌번호 생성과 중복 시 재시도
- `memberId`를 기준으로 한 회원별 계좌 목록 조회
- 계좌 상세와 현재 잔액 조회
- 계좌 개설 성공 후 목록 화면으로 이동하는 PRG 흐름

### 입금과 출금

- 입금·출금 금액의 숫자 형식과 0원 이하 입력 검증
- 잔액 부족 출금에 대한 글로벌 오류 표시
- 검증 실패 시 입력값을 유지한 채 같은 화면 반환
- 성공한 입금·출금의 잔액 반영과 거래내역 저장
- 계좌별 거래내역 최신순 조회를 지원하는 Memory Repository

### 화면

- Thymeleaf의 Model 출력, URL 링크, 반복과 조건부 표현
- `th:object`, `th:field`를 사용한 Form 바인딩
- 공통 navigation fragment
- 회원가입·로그인·계좌 화면의 주요 문구를 메시지 소스로 관리
- `GET /health` 상태 응답

## 현재 요청 흐름

```text
홈
-> 회원가입
-> 회원 ID를 전달해 계좌 개설
-> 회원별 계좌 목록
-> 계좌 상세
-> 입금 또는 출금
-> 계좌 상세
```

로그인 화면은 마련되어 있지만 로그인 판정과 세션 유지는 아직 연결하지 않았습니다. 계좌 조회는 로그인 회원이 아닌 요청 파라미터의 명시적인 `memberId`를 사용합니다.

## 구조

```text
HTTP 요청
  -> Controller
  -> Service
  -> Repository 인터페이스
  -> Memory Repository
```

- Controller는 요청 바인딩, 검증 결과 처리와 화면 이동을 담당합니다.
- Service는 회원 중복 검사, 계좌 개설과 잔액 변경 규칙을 담당합니다.
- Repository는 회원·계좌·거래내역의 저장과 조회를 담당합니다.
- Repository 인터페이스와 Memory 구현체를 분리해 저장 방식이 상위 계층에 직접 노출되지 않도록 구성했습니다.

현재 데이터는 애플리케이션 메모리에만 저장되므로 애플리케이션을 종료하면 사라집니다. H2와 JDBC 의존성은 빌드에 포함되어 있지만 JDBC Repository와 DB 저장 흐름은 아직 적용하지 않았습니다. 계좌이체와 세션 로그인도 현재 구현 범위에는 포함되어 있지 않습니다.

## 기술 구성

- Java 21
- Spring Boot 3.5.16, Spring MVC
- Thymeleaf
- Gradle 8.14.3
- JUnit 5, AssertJ
- Lombok

## 테스트

Repository와 Service 단위 테스트에서 다음 동작을 확인합니다.

- 회원 저장·조회와 중복 로그인 ID 거절
- 계좌 저장·조회, 회원별 조회와 계좌번호 충돌 재시도
- 입금·출금 후 잔액과 거래내역 반영
- 잘못된 금액과 잔액 부족 시 잔액·거래내역 불변
- 계좌별 거래내역 최신순 조회
- Spring 애플리케이션 컨텍스트 로딩

전체 테스트는 다음 명령으로 실행합니다.

```bash
./gradlew clean test
```

## 실행 방법

```bash
./gradlew bootRun
```

애플리케이션 실행 후 `http://localhost:8080`에서 시작할 수 있습니다.
